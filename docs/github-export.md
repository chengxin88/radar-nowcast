- `state/` 中的投递数据库、锁和任务状态。

导出时检查了正文中的已知配置凭据和接口令牌。推送模块测试使用的明确标注模拟用途的地址经核对为虚构测试值，按原文件保留；真实服务器配置继续保存在服务器上。逐文件校验清单可确认导出的业务代码与原发布包一致。

## 仓库启动器与原部署启动器

根目录新增 `run.sh`、`schedule.sh`，直接调用仓库的 `app/`，便于本地克隆后使用。

`deploy/run.sh`、`deploy/schedule.sh` 是阿里云原启动器：它们用于部署根目录，读取其私有 `config.env` 和 `.venv`，并通过 `current/app/` 调用发布包；不适合直接在仓库的 `deploy/` 子目录执行。

## 后续上线流程

1. 获取并记录准备上线的 Git 提交，在独立目录安装锁定依赖。
2. 配置当地的私有 `config.env`，先保持自动推送关闭，核对目标几何和官方资料映射。
3. 运行单元测试，再用 `rolling --dry-run` 检查实际资料和预览稿。
4. 将审核后的源码放到部署目录的一个新 `releases/` 子目录，保留旧版本及现有配置、状态和数据库。
5. 在无任务冲突时切换 `current` 到新发布目录，并验证状态和下一次预览；按既有维护流程管理计划任务与推送开关。
6. 如需回退，将 `current` 恢复到前一个已验证发布目录。
